## Paradigmas de conexão de aplicação

Você pode criar a sua aplicação usando vários paradigmas/arquiteturas:

- **Cliente/Servidor**: Servidor hospedeiro sempre ligado com IP fixo, cliente se comunica apenas com servidor e é imcapaz de se comunicar com outros clientes
- **P2P(Peer To Peer)**: Comunicação ponta a ponta, duas máquinas se conectam diretamente e trocam pacotes sem necessitar de servidor no meio

O cliente e servidor se tratam de dois processos com propósitos diferentes sendo o cliente que inicia o contato com o servidor e o servidor o processo que espera ser
contatado.

## Sockets

Estrutura do sistema operacional que permite que processos façam comunicação por rede, é necessário que existam sockets em ambas as pontas da comunicação em uma rede

# Web e HTTP

É o protocolo de nível de aplicação da web, que segue o modelo cliente/servidor. Algumas características:

- HTTP usa TCP para iniciar conexões
- HTTP é sem estado (*stateless*), isso significa que ele não salva histórico (estado) de conexões passadas
